# Packaging (RPM, DEB, Arch, AppImage)

Layout of the packages: `/usr/bin/{pdrive,pdrived,pdrive-app}`, private libraries in
`/usr/lib64/pdrive` (Fedora) or `/usr/lib/<triplet>/pdrive` (Debian, rpath set at build time with `PDSDK_RUNTIME_LIB_DIR`),
the Nautilus extension in the Nautilus extensions directory, `.ini` in
`/usr/share/cloud-providers`, icons, `.desktop`, `.mo` in `/usr/share/locale`, manual pages (`packaging/man/*.1`, plain troff) in `/usr/share/man/man1`.
Third-party licence inventories (`licenses/*.tsv`, generated by `scripts/audit-licenses.sh`) go to the documentation directory.

## Build inputs (no .NET, no network when building the packages)

1. Native archive `pdrive-native-linux-<x64|arm64>-<sdk>-<crypto>.tar.xz`: the two prebuilt libraries
   (`scripts/build-native.sh`, then `scripts/package-native.sh`), with SHA-256 sums and the MIT
   licence files. It is Source1 of the SRPM.
2. Source archive `pdrive-for-linux-<version>.tar.xz` (`scripts/make-source-tarball.sh`): project
   plus Rust crates vendored with `cargo vendor`. Source0 of the SRPM.

Locally: `scripts/build-packages.sh [rpm|deb|arch|appimage]` (podman or docker). Release: push a `v<version>` tag;
`.github/workflows/release.yml` fails unless the tag equals Cargo.toml, the spec and
`debian/changelog` and `packaging/arch/PKGBUILD` (`scripts/check-version.sh`). To bump the version by
hand, edit `[workspace.package]` in Cargo.toml, the workspace crates in Cargo.lock, `Version:` in the
spec, `pkgver` in the PKGBUILD and `debian/changelog`, or run `scripts/bump-version.sh patch|minor|major`.

Automatic release: run the workflow manually (Actions > release > Run workflow, on the default
branch) and choose `patch`, `minor` or `major` (0.1.1 -> 0.1.2, 0.2.0, 1.0.0). The `bump` job runs
`scripts/bump-version.sh`, commits, tags `v<version>` and pushes both, then the usual jobs release
that tag. The push uses `GITHUB_TOKEN`, so the new tag does not start a second run through the
`v*` trigger (do not switch the bump job to a PAT). The default branch must accept pushes from
`github-actions[bot]` (no protection rule blocking it). If the run fails before the release job
completes, the `rollback` job deletes the tag (and a draft release of it) and pushes a revert of
the bump commit, so the next run starts again from the same number.

The `release` job attaches the packages and `SHA256SUMS` to the release of the tag. If a release for
the tag already exists (published, or a draft from an earlier run), the files are uploaded to it with
`gh release upload --clobber` and its title, notes and state are left alone, so a re-run is safe.
Otherwise a draft is created; publishing it stays a manual step. Drafts are found by listing the
releases and filtering on `tag_name`, since they are not reachable by tag through the API.
`%global native_id` in the spec and `_native_id` in the PKGBUILD follow the revisions pinned in `scripts/build-native.sh`.

## Arch package

`packaging/arch/PKGBUILD`, built by `scripts/container/build-arch.sh` in an `archlinux:base-devel`
container (`makepkg` as an unprivileged user, same two local sources as the RPM, no network). The
result, `pdrive-for-linux-<version>-1-x86_64.pkg.tar.zst`, is installed with `pacman -U`. It is not
an AUR submission: the sources are release assets, not downloaded by the PKGBUILD.

## AppImage

`scripts/container/build-appimage.sh`, in a Debian 13 container (libadwaita >= 1.6). `linuxdeploy`
and its GTK plugin bundle GTK 4, libadwaita and the other libraries; the tools are pinned by version
and SHA-256. The AppImage holds `pdrive-app` (the default command), `pdrived` and `pdrive`. Not
included, because they live in system directories: the Nautilus extension (no emblems or menu
entries) and the libcloudproviders declaration (no account in the file manager sidebar).
`libproton_crypto.so` is loaded by path: the AppRun hook sets `PDRIVE_LIB_DIR` to the mount point
(`pdsdk::runtime_lib_dir`). The host must provide `fusermount3` (the daemon calls it), a Secret
Service provider, and a glibc at least as recent as Debian 13's (2.41).

## COPR

Upload the SRPM built by CI (`copr-cli build <owner>/<project> pdrive-for-linux-*.src.rpm`, or the
optional `copr` job: repository variable `COPR_PROJECT`, secret `COPR_CONFIG`). The SRPM carries both
sources, so the COPR build needs no network (`enable_net` can stay off; turn it on only if the spec
is changed to download sources or crates during the build). Limits: the SRPM carries the x86_64 native archive (COPR: x86_64 chroots only); prebuilt binaries
and vendored crates make the package unfit for the official Fedora repositories; the x86_64 libraries are
built on Ubuntu 24.04 (glibc 2.34+ required, satisfied by current Fedora).

## Migration from the development install

`scripts/install-system.sh` writes `/usr/local/share/cloud-providers/io.github.pdrive.PDrive.ini`.
Files under `/usr/local` belong to the administrator: the package scripts never delete them, they
only print a warning telling to remove that file (the account would be listed twice). The extension
is written by that script to the same system directory as the package; the package takes it over.
Per-user files (`~/.local/...`, `pdrive.service`) are not touched either.
